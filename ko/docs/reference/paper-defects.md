# 우리가 인용한 논문들에서 찾은 결함

**기록이 아니라 색인입니다.** 각 결함은 발견된 자리에 그대로 적혀 있습니다 — 인용문은 출처 안의 제자리에, 확인한 사람의 이름과 함께요. 이 파일이 있는 이유는 두 가지입니다. 세션이 *"이 논문 우리가 이미 읽었나, 그리고 물렸나"* 를 노트 전부를 뒤지지 않고 물을 수 있게, 그리고 **같은 저자·같은 그룹의 새 논문**이 들어올 때 앞선 발견이 함께 딸려오게.

**범위는 출처의 결함이지 우리 전사의 결함이 아닙니다.** 우리 실수는 브리프와 `engine/SESSION-HANDOFF.md` 규칙 절에 있습니다 — 멀쩡한 논문을 잘못 읽은 것은 여기 들어오지 않습니다.

**행을 추가할 때**는 양의 이름을 대고, 논문이 인쇄한 것과 옳은 것을 나란히 적고, 정정의 출처를 밝히고, 전말이 적힌 노트를 가리킵니다. **틀린 값이 조용히 틀린 답을 낼 수 있으면 게이트가 그걸 잡는지도 적습니다.**

## 논문 결함은 아닌데 그렇게 읽히는 것 둘

- **SeaFreeze `water2`** 가 **자기 매듭 상자 안에서 음의 밀도**를 냅니다 — 인쇄된 유효 범위가 실행되는 범위가 아닙니다. 이건 *라이브러리*가 자기 문서보다 나쁘게 동작하는 것이고 사전등록된 스윕으로 찾았습니다. 이후 출처를 구울 때 **실효 천장을 재는 것**이 규칙이 된 이유입니다. `engine/water2-context-notes.md`.
- **IF97 PDF 의 텍스트층이 10의 거듭제곱을 전부 떨어뜨렸습니다.** 인쇄가 아니라 *추출* 실패이고, 그래서 기계 추출한 수치표는 **같은 추출을 탄 검산값이 아니라 다른 렌더링에 대조**합니다. `engine/steam-context-notes.md`.

## 패턴이 말하는 것

**실제로 전사한 출처들에서 결함 열둘.** 다섯은 인쇄된 값 하나의 자릿수·부호 실수(#1·#6·#8·#9·#10), 셋은 논문이 자기와 어긋나는 것(#4·#5·#7), 하나는 주장 범위가 그 뒤의 데이터보다 넓은 것(#8), 하나는 귀속이 엉뚱한 주인을 가리키는 것(#2), 하나는 인용 연도가 틀린 것(#11), 하나는 맞는 단위를 엉뚱한 양에 옮겨 붙인 것(#12).

여기서 지금 우리가 일하는 방식 셋이 나왔습니다.

- **1차 출처에서 전사합니다.** #1 은 2차 표기에 있었고 1차는 깨끗했습니다 — 그 차이가 우리 위성들이 사는 자리에서 750 K 였습니다.
- **전사는 논문이 따로 진술한 것에 대조합니다** — 자기가 인쇄한 외삽점, 자기 폐합, 또는 두 번째 식. #7 과 #9 가 그렇게 잡혔고, #5 는 논문이 자기 검산을 못 통과할 때 무슨 일이 생기는지입니다.
- **수의 라벨은 본문 그 자리에서 확인합니다.** #2 는 문장을 통째로 읽기 전까지 멀쩡해 보였습니다.
