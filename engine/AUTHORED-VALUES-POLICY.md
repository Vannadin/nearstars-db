# Authored values — the policy (owner decision, 2026-09-04)

**Owner's words, verbatim** (relayed by the directing seat, 2026-09-04 afternoon):

> *"소비자 없음 문제는 우리가 특정 목적이 아닌 general한 도구로써 만들기 위해서 무시해야 할 문제고, 이렇게 되면
> 규율을 좀 느슨하게 해야겠어. 모순이 없는 한 창작을 허용해야지 뭐. 자기장 배선을 잇기 위해서 필요한 값들 같은거.
> 이쪽은 우리 창작이다 표시를 해두고."*

This is **not** "loosen the discipline". It is two narrow changes and four things that do not change.

## What changes (two things)

1. **C5 — "no machinery without a consumer" — yields to generality.** The engine is a general tool, not a
   roster-specific one. *"No roster body needs it"* is **no longer a reason to refuse** building or wiring a
   node. (C5 itself, the interior finding of 2026-08-30, is untouched; it is the *rule named after it* that
   yields.)
2. **Authored values are allowed — in empty places only.** When a mechanism needs a value that **no held
   source supplies**, this project may supply it, **provided it contradicts nothing that is grounded.** Such a
   value is *authored*, and it is marked as such everywhere it appears.

## What does not change (four things — read these as the larger half)

1. **Provenance honesty.** An authored value is labelled *authored*, in the code (`grade: authored`), in the
   graph, in the methodology row and in any board. 2026-09-04 was spent repairing false "cached" labels
   (owner list O4); this policy must not manufacture a new class of them.
2. **A source, where one exists, is used.** Authoring is for gaps. A held source one dislikes is not a gap.
3. **Two sources that disagree are a finding, not a licence.** Disagreement is recorded as a width or a
   named tension (C25 is the form), never resolved by authoring a third number.
4. **Pre-registration stands.** Authoring a *value* is allowed; choosing a *branch after seeing the result* is
   not. Outcomes are still named before the numbers, constants still do not move to land a printed number
   (C14 §Not adopted), and refusals still name what is missing.

## How an authored value is written

The grade `authored` (added to `payload.GRADES` and `chain.yaml` `grades` on 2026-09-04) means: *a value this
project supplied; no held source gives it; it contradicts nothing grounded.* `judgment` is **not** reused for
this — its 14 existing uses are choices *between published options*, and mixing authored values into that
label would dilute it (the failure this day was spent undoing in the other direction).

Every `authored` result must carry, in its `notes`, both of:

- **`gap:`** — why the place is empty: which sources were looked for (cache, ADS) and found not to give it.
- **`consistent-with:`** — what grounded quantity or bound was checked against, and how the value sits inside it.

`payload.Result` refuses an `authored` result that lacks either marker. A number without its two reasons is
a number the next seat cannot trust, and it is refused at construction, not at review.
