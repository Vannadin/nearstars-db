# BurnMan 전용 대조 환경 — 런타임 의존성이 아니고, engine/requirements.txt 와 별개다.
#
# 왜 두 벌인가. burnman 2.1.0 은 sympy 를 요구하고, sympy 1.14.0 은 mpmath<1.4 를
# 요구한다. engine/requirements.txt 는 mpmath==1.4.1 을 페르미 적분의 두 번째
# 오라클로 쓰려고 박아 둔 것이라, 그 핀을 의존성 편의로 내리지 않는다. 그래서
# BurnMan 은 자기 venv 로 간다 — engine/.venv 는 읽기만 하고 손대지 않는다.
#
# 라이선스는 NOTICE 의 «ENGINE RUNTIME DEPENDENCIES» 줄이 말한다. burnman 은
# 설치본에 라이선스 파일이 없어(sdist·wheel 둘 다) 그 줄이 기대는 GPL v2 전문은
# 저장소 쪽 사본이다.
#
#     python3 -m venv engine/.venv-burnman
#     engine/.venv-burnman/bin/pip install -r engine/requirements-burnman.txt
#     engine/.venv-burnman/bin/python -c "import burnman; print(burnman.__version__)"
#
# ⚠ 이 목록은 핀 29 줄이고, 설치가 실제로 받는 것은 28 개다. 재현 조건은 이렇다.
#
#   29 archives downloaded · 28 pip-installed · the difference is `setuptools`,
#   required unversioned by `osqp`; the venv's bundled `setuptools 58.0.4` (from
#   macOS `/usr/bin/python3`) already satisfies it, so the closure's
#   `setuptools 82.0.1` was fetched and not installed. ~~Reproduces only from a venv
#   created by the same interpreter.~~ — 취소. 58.0.4 를 핀한 뒤로는 어떤 인터프리터로
#   만든 venv 든 이 파일에서 58.0.4 를 받는다. 남는 조건은 인터프리터가 아니라 **파이썬
#   판**이다: llvmlite 0.42.0 · numba 0.59.1 · scipy 1.13.1 이 판별 wheel 을 내므로,
#   맞는 문장은 «python 3.9 venv 에서 재현된다» 이다.
#
#   사슬은 osqp -> cvxpy -> burnman 이고, 설치 로그가 그 자리를 적는다 —
#   «Requirement already satisfied: setuptools … (from osqp>=1.0.0->cvxpy<2.0,>=1.3->
#   burnman==2.1.0) (58.0.4)». `pip freeze` 는 setuptools 와 pip 을 원래 안 찍는다.
#   ⚠ 폐쇄가 받은 판 82.0.1 은 병렬석이 잰 수다 — 이 설치는 그 아카이브를 안 받았으므로
#   여기서 되짚을 수 없다.
#   ⚠ 두 파일이 한 줄 다르다, 일부러. **환경은 이 파일**(29 줄, setuptools 포함)이고,
#   **관측은 `191-burnman-freeze.txt`**(28 줄) 다 — `pip freeze` 가 setuptools 와 pip 을
#   안 찍어서 생기는 차이이지 둘이 어긋난 것이 아니다.
#   그래서 아래 마지막 줄에 **`setuptools==58.0.4` 를 적는다** — 인터프리터에 따라 두 환경이
#   나오는 목록은 핀이 아니기 때문이다. 58.0.4 는 191 의 검사 넷이 실제로 딛고 선 판이라
#   «검사한 것을 핀한다» 이지, 아무도 고르지 않은 수를 고르는 것이 아니다.
#   그 아카이브는 손에 들고 있다 — setuptools-58.0.4-py3-none-any.whl, 816539 B, sha256
#   69cc739bc2662098a68a9bc575cd974a57969e70c1d58ade89d104ab73d79770, py3-none-any 라
#   python 3.9 에서 그대로 풀린다. 이 목록은 우리가 들고 있는 아카이브만 이름 댄다.
